## 1. Technical problem

Conventional AI memory commonly retrieves context through semantic search, embeddings, vector similarity, or repeated natural-language reconstruction. Those mechanisms may require model inference, approximate nearest-neighbor search, token transport, or an auxiliary semantic index.

RM-0001 discloses a different memory primitive: information is represented and addressed through deterministic state/trajectory relations, with the design goal that a known resolutive address can be resolved without asking a language model to rediscover the stored content.

This disclosure does **not** claim that arbitrary natural-language queries can presently be resolved in O(1), nor that the implementation has demonstrated superior end-to-end performance against vector-memory systems.

## 2. Definitions and assumptions

- **State:** a machine-representable configuration participating in a deterministic transition system.
- **Trajectory:** an ordered relation between states produced by a transition rule.
- **Resolutive address:** a compact identifier sufficient to select a previously registered trajectory/route in the memory engine.
- **Route resolution:** deterministic lookup of a known address to the corresponding stored trajectory record.
- **Payload:** information associated with the trajectory or route.
- **Integrity digest:** cryptographic or deterministic digest used to verify reconstructed/retrieved information; it is not itself assumed to contain the information.
- **Snapshot:** persisted representation of the memory engine and its registered state.
- **Semantic router:** optional mechanism that maps an external symptom/query to a known route. It is logically distinct from route resolution itself.

The O(1) property discussed here applies to the indexed resolution of an already-known resolutive address under the implemented data structure. It must not be generalized to arbitrary semantic understanding, persistence I/O, network latency, or reconstruction cost without separate evidence.

## 3. Technical solution

The memory is separated into two conceptual stages:

1. **Route formation / registration** — information is converted into or associated with a deterministic trajectory and registered under a resolutive address.
2. **Route resolution** — given the address, the engine directly selects the registered trajectory/state record rather than performing a semantic similarity scan over all memories.

Abstractly, let `A` be the address space and `T` the registered trajectory space. The core resolver implements a mapping

`R : A -> T`

such that, for an address `a` already present in the registry,

`R(a) = T_a`.

A practical implementation may realize `R` with a hash-indexed table or equivalent constant-average-time structure. The trajectory itself may then reference payload, state transitions, metadata, integrity information, or subsequent deterministic operations.

The architecture deliberately distinguishes:

`external query -> semantic/router stage -> resolutive address -> deterministic resolver -> trajectory/payload`

This separation is important: the semantic/router stage may evolve independently and may use rules, compact models, or other mechanisms. The resolutive memory core does not require an LLM to perform the final known-address lookup.

## 4. Disclosed technical features

1. Separation of semantic interpretation from deterministic memory resolution.
2. Persistent resolutive addresses associated with trajectory/state records.
3. Direct resolution of known routes without LLM token exchange.
4. Local-first operation compatible with offline edge devices.
5. Optional integrity verification independent of semantic routing.
6. Snapshot/persistence boundary distinct from transient query-routing state.
7. Architecture suitable for hierarchical deployment in which edge memories can synchronize selected state with higher-level memories.

## 5. Algorithm / state transition

Minimal normative model:

```text
REGISTER(payload, trajectory_metadata):
    trajectory := deterministic_encode_or_associate(payload, trajectory_metadata)
    address := derive_or_allocate_address(trajectory)
    registry[address] := trajectory
    return address

RESOLVE(address):
    if address not in registry:
        return UNKNOWN
    return registry[address]

QUERY(external_signal):
    address := semantic_router(external_signal)   # optional / separate layer
    if address == UNKNOWN:
        return OPEN_QUESTION
    return RESOLVE(address)
```

A conforming implementation must not describe `QUERY` as O(1) merely because `RESOLVE` is O(1). Any complexity claim must name the exact operation being measured.

## 6. Worked example

Suppose an edge agent registers a known operational state `S` and receives address `a_42`. Later another component already possessing `a_42` requests the memory. The resolver performs `R(a_42)` and obtains the registered trajectory/state record directly. No natural-language prompt needs to be generated between those two operations.

If the component only supplies a free-form sentence, an additional router must first infer or select `a_42`; that is a different problem and may have different computational complexity and error modes.

## 7. Reproducibility and evidence

Existing Memoria.ia development has exercised deterministic route resolution and an experimental v0.96 semantic-routing line. Reported internal v0.96 experiments include a split accuracy of 0.9375, known recall of 0.9167, threshold regions with accuracy 1.0, and open-set false-positive 0.0 in the tested experimental setup.

Those figures are development evidence, not an independent benchmark and not a claim of general semantic-memory superiority. Exact scripts, datasets, seeds, commits, and CI artifacts should be pinned in a later revision before RM-0001 advances to VALIDATED.

## 9. Security, privacy, and failure modes

- Possession of an address must not automatically imply authorization to read its payload.
- Address collision, corrupted snapshots, stale routing metadata, and integrity mismatch must fail closed where confidentiality or correctness is required.
- A semantic router can select the wrong valid address even when the core resolver itself is deterministic.
- Private/local trajectories must not be synchronized merely because they are resolvable.
- Hashes/digests verify integrity but are not treated as reversible storage unless a separate reversible construction demonstrates that property.

## 10. Limitations and unresolved questions

At this revision:

- arbitrary natural-language understanding is not solved by the core resolver;
- the experimental symptom/query-to-route index is conceptually separate and may not be fully contained in all snapshots;
- HTTP API, authentication, tenant isolation, and production policy are separate product concerns;
- independent comparisons against Mem0, Zep, Letta, vector databases, or other memory systems remain required;
- no claim of information-theoretic compression follows merely from trajectory representation;
- O(1) refers only to the specified known-address lookup operation.

## 11. Related work and prior art

Relevant comparison classes include hash tables/key-value stores, content-addressed storage, associative memories, vector databases, event/state-machine persistence, agent-memory frameworks, and deterministic automata. RM-0001's intended distinction is the explicit use of trajectory/state relations as the memory abstraction together with a strict separation between route discovery and route resolution.

A publication-grade prior-art survey is still required before the status can be raised beyond EXPERIMENTAL.
