## 1. Technical problem

Conventional storage systems identify data by location, key, object ID, or content hash. A content hash can verify data, but by itself does not generally reconstruct arbitrary source information. RM-0002 discloses a trajectory-centric addressing model in which information is associated with a deterministic sequence of state relations, and retrieval operates from compact route/state descriptors plus integrity metadata.

This disclosure does **not** claim that arbitrary information can currently be reconstructed from a single cryptographic hash plus length. Any such stronger reversible construction requires separate experimental proof.

## 2. Definitions

- **Initial state (`S0`)**: state at the beginning of a trajectory segment.
- **Final state (`Sn`)**: state after `n` transitions.
- **Transition rule (`F`)**: deterministic operation producing the next state from current state and transition input.
- **Trajectory (`T`)**: ordered sequence `(S0, S1, ..., Sn)` or an equivalent compact representation of the state relations.
- **Step count (`n`)**: number of transition steps; when one transition corresponds to one source bit, this can equal the processed bit length.
- **Trajectory descriptor (`D`)**: metadata sufficient to identify/replay/select the trajectory under a defined reversible or indexed construction.
- **Integrity hash (`H`)**: digest used to verify recovered content; not treated as a standalone reversible encoding.

## 3. Technical solution

The disclosed architecture stores or derives information through state relations rather than treating each source fragment as an unrelated object.

Abstractly:

`S_(i+1) = F(S_i, b_i, c_i)`

where `b_i` is source information or a source-dependent transition choice and `c_i` is deterministic context such as step index, layer, or rule selector.

A trajectory descriptor may contain a subset such as:

```text
D = {
    initial_state,
    final_state,
    step_count,
    rule_version,
    integrity_hash,
    optional checkpoints/index metadata
}
```

The exact minimal descriptor depends on whether the chosen transition system is analytically reversible, uniquely constrained by state relations, or requires auxiliary checkpoints/search.

The retrieval contract is therefore:

```text
RECOVER(D):
    candidate := reverse_or_resolve_trajectory(D)
    if HASH(candidate) != D.integrity_hash:
        return INVALID
    return candidate
```

The integrity hash is a verifier, not the source of the candidate.

## 4. Disclosed technical features

1. Encoding information through deterministic relations between successive states.
2. Use of trajectory descriptors rather than only fragment-by-fragment storage identifiers.
3. Explicit separation of reconstruction metadata from integrity verification.
4. Support for hierarchical/chunked trajectories, allowing long streams to be decomposed into smaller state-space problems.
5. Ability to introduce checkpoints or layered relations when direct inversion of a large trajectory is computationally infeasible.
6. Compatibility with bit-, byte-, or block-level transition alphabets.
7. Potential use of `initial_state + final_state + step_count + integrity_hash` as a target descriptor form, subject to uniqueness/recoverability tests.

## 5. Hierarchical decomposition

For a source of `N` transition units, the system may partition it into blocks of size `k`:

`N = m*k + r`

Each block produces a local trajectory descriptor. A higher layer can then encode relations among those descriptors or terminal states.

Conceptually:

```text
source bits/bytes
      ↓
local trajectories
      ↓
block states/descriptors
      ↓
relation layer 2
      ↓
relation layer 3 ...
```

This is intended to reduce the inversion/search domain for each subproblem. It does not, by itself, prove compression or guaranteed efficient inversion.

## 6. Worked example

Assume a reversible transition family `F_v1` and an 8-step source segment. The encoder starts from `S0`, applies eight source-dependent transitions, and obtains `S8`. It records:

```text
S0
S8
n = 8
rule_version = F_v1
H = hash(original_segment)
```

A resolver attempts to invert or constrain the 8-step trajectory using the known transition rules and endpoints. If exactly one source segment is recovered and its digest equals `H`, recovery succeeds. If multiple candidates remain or none verifies, the descriptor is insufficient for that construction and must include additional metadata/checkpoints.

## 7. Evidence and current state

Prior development explored reversible state machines, 63-bit state spaces, macro/micro transition rules, beam-search reconstruction, hierarchical bit relation analysis, and a trajectory-generator project targeting recovery from compact terminal descriptors.

Some earlier experiments recovered only partial information (roughly near chance-level bit accuracy in certain beam-search variants), so they are evidence of exploration rather than proof of general reversibility.

RM-0002 therefore records the architecture and target descriptor model while explicitly leaving the minimal sufficient descriptor as an experimental question.

## 8. Failure modes

- many-to-one state transitions can destroy recoverability;
- endpoint pairs may admit multiple valid trajectories;
- search complexity may grow exponentially with step count;
- insufficient checkpoints can make reconstruction impractical;
- hash verification can reject wrong candidates but cannot select the correct candidate if no reconstruction mechanism produces it;
- apparent storage reduction may merely move information into model/rule/checkpoint metadata.

## 9. Compression boundary

No compression claim is implied unless total encoded size is measured as:

`descriptor + rules + checkpoints + indexes + integrity metadata`

against the original source under a reproducible corpus and decoder. Virtual/logical compactness is not sufficient evidence of information-theoretic or practical compression.

## 10. Relationship to RM-0001

RM-0001 defines the known-address memory resolver. RM-0002 defines how trajectory descriptors may represent/recover information associated with those addresses. A system may implement RM-0001 without solving the stronger reversible-trajectory problem in RM-0002.

## 11. Related work

Relevant comparison classes include reversible computing, finite-state transducers, arithmetic/coding theory, content-addressed storage, hash chains, Merkle structures, error-correcting codes, constrained sequence decoding, and hierarchical compression/indexing.
