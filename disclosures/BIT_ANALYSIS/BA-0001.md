## Technical problem

Analyze information by relationships between neighboring bit/byte blocks and recursively form higher-order relation layers, with optional adaptive protection assigned according to observed profiles.

## Core disclosure

Given an input sequence partitioned into blocks `B_i`, define a relation transform `R(B_i, B_{i+1})`. The resulting relation symbols form a new sequence that can itself be partitioned and related recursively:

`L_0 = {B_0, B_1, ...}`

`L_{k+1} = { R(L_k[2j], L_k[2j+1]) }`.

Any reconstruction claim must account for side information required to invert each relation layer. The hierarchy is therefore an analysis/representation mechanism by default, not automatically a compression scheme.

## Disclosed features

1. Pairwise block-relation transform.
2. Recursive higher-order relation layers.
3. Variable block granularities for empirical study.
4. Profile-dependent/adaptive protection assignment.
5. Explicit accounting of protection overhead versus uniform policies.
6. Separation of corruption resilience from compression claims.

## Reference evidence

The public `bit.analyze` repository contains a validation commit for adaptive protection (`1f64dca...`) and a benchmark comparing adaptive versus uniform protection overhead (`b5a4fe7...`), along with subsequent implementation and documentation commits.

## Limitations

- Relation layers can increase metadata and total storage.
- Error recovery requires sufficient redundancy or constraints; it is not guaranteed by hierarchy alone.
- No net compression ratio is claimed without counting all side information, indexes, checksums, and protection data.
- Generalization across data distributions remains experimental.
